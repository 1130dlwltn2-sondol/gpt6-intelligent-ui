# 1장. AI 답변이 도구가 되는 시대

## 학습 목표

- 문장형 텍스트, 표, 대화형 요소의 차이를 설명할 수 있다
- 질문의 성격에 따라 적절한 답변 형태를 요청할 수 있다
- 시각적 요소가 정확도를 보장하지 않는다는 점을 이해한다

## 개념 설명

2026년 10월 7일, OpenAI는 GPT-6와 함께 Intelligent UI라는 기능을 Chat 탭에 공개하기 시작했다. 이전까지 AI 챗봇의 답변은 대부분 문장 형태였다. 질문을 하면 문단으로 답이 돌아왔고, 표가 필요하면 사용자가 따로 요청해야 했다. Intelligent UI는 이 방식을 바꿨다. 모델이 질문의 성격을 보고 문장, 표, 차트, 버튼, 폼, 계산기 같은 대화형 요소 중에서 적절한 형식을 직접 골라 답한다.

답변 형태는 크게 세 가지로 나눌 수 있다. 첫째는 문장형 텍스트다. 설명, 요약, 의견처럼 흐름이 중요한 내용에 어울린다. 둘째는 표와 목록이다. 비교, 정리, 순서가 있는 안내에 강하다. 여러 항목을 나란히 놓고 싶을 때 문장보다 훨씬 읽기 쉽다. 셋째는 대화형 요소다. 버튼을 누르거나 값을 입력하면 결과가 바뀌는 계산기, 슬라이더, 차트, 간단한 게임이 여기에 속한다. 읽기만 하는 답변이 아니라 만지면서 배우는 답이다.

여기서 꼭 짚고 넘어가야 할 점이 있다. 보기 좋은 형식이 정확한 내용을 보장하지는 않는다는 것이다. 표가 깔끔하게 정리돼 있어도 그 안의 숫자가 틀릴 수 있고, 계산기 모양의 UI가 나와도 수식이 잘못됐을 수 있다. 형식은 이해를 돕는 도구일 뿐, 내용의 정확도와는 별개 문제다. 이 책 전체에서 반복할 원칙이다. 멋진 표를 받았다면 그 다음에는 반드시 내용을 검증한다.

반례도 알아두자. 모든 질문에 표나 대화형 요소가 필요한 것은 아니다. 단순한 사실 확인이나 짧은 설명에는 문장 한두 개가 가장 빠르고 정확하다. 공식 발표에서도 모델이 질문에 따라 단순한 텍스트 답변이 가장 유용하다고 판단하면 그렇게 답한다고 밝혔다. 형식을 요청하는 것은 선택지이지 의무가 아니다.

## 언제 쓰는가

- 표와 목록: 두 가지 이상을 비교하거나, 순서를 정리하거나, 항목별 특징을 나란히 보고 싶을 때
- 대화형 요소: 값을 바꿔가며 결과를 탐색하고 싶을 때, 단계별로 직접 조작하며 배우고 싶을 때
- 문장형 텍스트: 단순한 설명, 짧은 답, 의견이나 요약이 필요할 때

## 사전 준비

- ChatGPT 계정 (무료 계정으로 시작 가능)
- 웹브라우저 (크롬, 엣지, 사파리 등)
- 메모장이나 노트 앱 (실습 결과를 기록용)

## 단계별 실습

1단계. 같은 질문을 문장으로만 요청한다. 예: "예금 이자의 원리를 설명해줘." 답을 읽고 이해한 정도를 메모한다.

2단계. 같은 질문을 표 형태로 요청한다. 예: "예금 이자의 원리를 표로 정리해줘." 1단계 답변과 비교해 무엇이 더 이해하기 쉬웠는지 기록한다.

3단계. 대화형 요소가 가능한지 확인한다. 예: "이자율을 바꿔가며 결과를 비교할 수 있는 형태로 보여줘." 화면에 버튼이나 입력 칸이 나타나는지, 나타나지 않으면 어떤 답이 오는지 기록한다. 실제 화면 미확보: 이 책의 그림은 모식도이며 실제 UI가 아니다.

4단계. 반례를 찾는다. 표나 대화형 요소가 오히려 방해가 되는 질문을 하나 만들어 요청해 본다. 예: "오늘의 날짜를 알려줘." 형식보다 내용이 중요한 경우를 확인한다.

## 복사해서 쓰는 프롬프트

프롬프트 1. 형식을 스스로 판단하게 하기

```
초등학생도 이해할 수 있게 예금 이자의 원리를 먼저 5문장으로 설명하고, 이해를 돕는 표가 유용한지 판단해줘. 표가 필요 없다면 이유를 말해줘.
```

프롬프트 2. 세 가지 형태를 나란히 비교하기

```
예금 이자의 원리를 (1) 문장 설명, (2) 표, (3) 대화형 요소 세 가지 형태로 각각 보여줘. 각 형태의 장단점을 한 줄씩 덧붙여줘.
```

## 입력 예시

위 프롬프트 1을 그대로 복사해 Chat 탭의 입력창에 붙여넣고 전송한다. 계정 상태에 따라 대화형 요소가 나타나지 않을 수 있다. 그 경우 텍스트와 표로 답이 오는데, 이것도 정상적인 결과다.

## 성공 예시

질문의 성격에 맞는 형식이 돌아오고, 각 형태의 차이를 한 문장으로 설명할 수 있다. 예: "표는 이자율별 결과를 한눈에 비교하기 좋았고, 문장은 원리 이해에 도움이 됐다. 대화형 요소는 내 계정에서 표시되지 않아 표로 대체됐다."

## 실패 예시

형식에만 집중해 내용을 확인하지 않는다. 예: 이자 계산 표의 숫자를 검산하지 않고 그대로 믿는다. 또는 대화형 요소가 나오지 않는다고 해서 실습을 중단한다. 형식은 요청의 일부일 뿐, 내용 검증이 본질이다.

## 오류 해결

- 표가 나오지 않을 때: "위 내용을 표로 다시 정리해줘."라고 한 번 더 요청한다. 그래도 안 되면 텍스트로 정리된 내용을 직접 표로 옮겨 적는다.
- 대화형 요소가 나오지 않을 때: 2장의 가용성 확인 절차를 따른다. 지원되지 않는 환경에서는 표와 계산 절차를 요청하는 대체 프롬프트를 쓴다.
- 답이 너무 길 때: "핵심만 5줄로 줄여줘."라고 요청한다.

## 완료 점검

- [ ] 문장, 표, 대화형 요소의 차이를 한 문장씩 설명할 수 있다
- [ ] 질문의 성격에 따라 적절한 형식을 고를 수 있다
- [ ] 시각적 요소가 정확도를 보장하지 않음을 설명할 수 있다

## 확인 문제

1. 다음 중 대화형 요소가 가장 유용한 경우는? (1) 오늘 날짜 확인 (2) 이자율별 예금 결과 비교 (3) 단어 뜻 질문. 정답: (2). 값을 바꿔가며 결과를 탐색하는 학습에는 대화형 요소가 어울린다.

2. 표로 정리된 답변을 받았을 때 가장 먼저 해야 할 일은? 정답: 표 안의 숫자나 사실을 검산·확인하는 것. 형식은 이해를 돕지만 정확도를 보장하지 않는다.
