# 5장. 대화형 계산기 설계

## 학습 목표

- 계산기에 필요한 입력값, 단위, 공식, 예외 조건을 지정할 수 있다
- AI가 만든 계산 결과를 손으로 검산할 수 있다
- 대화형 UI가 없을 때 표와 계산 절차로 대체할 수 있다

## 개념 설명

계산기는 Intelligent UI의 대표적인 활용이다. 값을 입력하면 결과가 바로 바뀌는 도구는 "만지면서 배우는 답"의 가장 직접적인 형태다. 공식 발표에서도 저축액 증가를 탐색하는 계산기, 식사비 나누기 도구가 예시로 소개됐다. 하지만 계산기를 잘 쓰려면 요청하는 쪽에서 설계도를 줘야 한다. 설계도의 네 요소는 입력값, 단위, 공식, 예외 조건이다.

입력값은 사용자가 바꿀 수 있는 변수다. 예금 계산기라면 원금, 연이율, 기간이 입력값이다. 단위는 숫자의 의미를 정한다. 원금은 원, 연이율은 퍼센트, 기간은 년이다. 단위가 빠지면 5가 5원인지 5%인지 알 수 없다. 공식은 계산의 근거다. 단리인지 복리인지, 세전인지 세후인지를 명시한다. 예외 조건은 계산이 성립하지 않는 경우다. 이자율이 0이거나 음수일 때, 기간이 0일 때 어떻게 처리할지를 정한다.

이 네 요소를 지정하는 이유는 두 가지다. 첫째, AI가 빈틈을 추측으로 메우는 것을 막는다. 공식을 지정하지 않으면 AI가 임의로 단리를 쓸지 복리를 쓸지 정한다. 둘째, 검증 기준이 생긴다. 공식과 단위가 명확하면 손계산으로 결과를 확인할 수 있다. 계산기는 숫자를 다루는 도구이므로 검증이 특히 중요하다. 1장에서 말한 원칙이 여기서 가장 강하게 적용된다. 멋진 계산기라도 수식이 틀리면 소용없다.

대화형 UI가 지원되지 않는 환경에서는 같은 설계도로 표와 계산 절차를 요청한다. 입력값의 조합을 몇 가지 정해 표로 만들고, 각 셀의 계산 과정을 단계별로 적는다. 손으로 따라 계산할 수 있으면 학습 효과는 대화형과 크게 다르지 않다.

## 언제 쓰는가

- 변수에 따라 결과가 어떻게 바뀌는지 탐색하고 싶을 때 (이자, 대출, 할인)
- 공식을 외우는 것이 아니라 이해하고 싶을 때
- 같은 계산을 여러 조건으로 반복해야 할 때

## 사전 준비

- 4장에서 만든 비교표 (입력값 후보를 고르는 데 활용)
- 계산기 주제 하나 (예: 예금 이자)
- 메모장, 계산기 앱 (검산용)

## 단계별 실습

1단계. 설계도를 쓴다. 입력값(원금, 연이율, 기간), 단위(원, %, 년), 공식(복리, 1년 복리), 예외 조건(이자율 0, 기간 0)을 메모한다.

2단계. 계산기를 요청한다. 아래 프롬프트 1을 입력한다. 대화형 UI가 나오면 값을 바꿔가며 결과를 확인하고, 나오지 않으면 표와 계산 절차로 답이 오는지 확인한다.

3단계. 세 개의 수치를 직접 검산한다. 표나 계산기의 결과 중 세 가지를 골라 손이나 계산기 앱으로 다시 계산한다. 공식: 복리 = 원금 × (1 + 연이율)^기간.

4단계. 예외 조건을 테스트한다. 이자율 0, 기간 0 같은 값을 넣어 보고 결과가 합리적인지 확인한다.

## 복사해서 쓰는 프롬프트

프롬프트 1. 계산기 요청 (대화형 우선, 대체 경로 포함)

```
원금·연이율·기간을 바꿔 결과를 비교하는 학습용 계산기를 구성해줘. 수식과 단위를 함께 표시하고, 상호작용 UI가 안 되면 Markdown 표와 계산 절차로 제공해줘.
```

프롬프트 2. 설계도를 명시한 요청

```
입력값: 원금(원), 연이율(%, 소수 둘째 자리), 기간(년). 공식: 1년 복리, 세전. 예외: 이자율 0이면 원금 그대로, 기간 0이면 원금 그대로. 위 조건으로 예금 이자 계산기를 만들어줘. 수식과 단위를 함께 표시해줘.
```

## 입력 예시

프롬프트 1을 입력한다. 지원 환경에서는 입력 칸과 결과가 연동된 계산기가, 미지원 환경에서는 원금·이자율·기간 조합표와 계산 절차가 돌아온다.

## 성공 예시

세 개의 수치를 손으로 검산해 모두 일치한다. 예: 원금 100만원, 연이율 5%, 3년 → 100 × 1.05^3 = 115.7625만원. 표의 값과 일치함을 확인한다.

## 실패 예시

공식을 지정하지 않고 "이자 계산기 만들어줘."라고만 요청한 뒤, 단리인지 복리인지 모른 채 결과를 받아들인다. 또는 검산 없이 계산기의 숫자를 그대로 인용한다.

## 오류 해결

- 단위 표기가 없을 때: "모든 숫자에 단위를 붙여줘."라고 요청한다.
- 단리와 복리가 섞여 있을 때: 사용할 공식을 하나로 지정해 다시 요청한다.
- 결과가 이상할 때: 예외 조건(이자율 0, 기간 0)을 넣어 어디서 틀어지는지 찾는다.
- 대화형 UI가 없을 때: 프롬프트 1의 대체 경로(표와 계산 절차)를 그대로 쓴다.

## 확인 문제

1. 원금 100만원, 연이율 5%, 기간 3년, 1년 복리(세전)의 만기 금액은? 정답: 약 115.76만원. 계산: 100 × 1.05^3 = 115.7625.

2. 계산기 요청에 단위를 꼭 명시해야 하는 이유는? 정답: 단위가 빠지면 숫자의 의미가 불분명해지고, 검산 기준도 사라지기 때문이다.
