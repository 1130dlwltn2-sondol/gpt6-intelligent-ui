# 8장. 최종 프로젝트: 나만의 학습 UI

## 학습 목표

- 지금까지 만든 도구를 하나의 학습 패키지로 통합할 수 있다
- 초보자용 사용설명서를 작성할 수 있다
- 제3자가 재현 가능한지 확인하고 대체 경로를 제공할 수 있다

## 개념 설명

이 장은 이 책의 모든 내용을 하나로 묶는 최종 프로젝트다. 1장에서 답변 형태를 이해했고, 2장에서 환경을 확인했으며, 3장에서 질문 구조를 배웠다. 4장에서 비교표를, 5장에서 계산기를, 6장에서 퀴즈를 만들었고, 7장에서 검증 방법을 익혔다. 이제 이 결과물들을 개인 맞춤형 학습 도구 3종으로 정리한다. 개념 비교표, 실습 체크리스트, 변수 조절 계산기가 그 세 가지다.

세 도구의 역할은 다르다. 개념 비교표는 배운 내용을 정리하는 도구다. 4장의 비교 기준을 적용해 주제별 핵심 차이를 한눈에 본다. 실습 체크리스트는 실행을 돕는 도구다. 각 장의 완료 점검을 모아 학습 진도를 관리한다. 변수 조절 계산기는 탐색을 돕는 도구다. 5장의 설계도(입력값, 단위, 공식, 예외 조건)를 적용해 값을 바꿔가며 결과를 확인한다.

통합의 핵심은 사용설명서다. 도구가 있어도 쓰는 법을 모르면 소용없다. 사용설명서에는 사용 조건, 입력 예시, 예상 오류, 수동 검증법을 포함한다. 사용 조건은 어떤 환경에서 동작하는지다. 입력 예시는 무엇을 넣으면 되는지다. 예상 오류는 자주 틀리는 지점이다. 수동 검증법은 도구의 결과를 손으로 확인하는 방법이다.

마지막으로 재현 가능성을 확인한다. 만든 패키지를 다른 사람에게 주고, 처음부터 같은 순서로 따라 하게 한다. 막히는 지점이 나오면 그 지점의 설명을 고치거나 대체 경로를 제공한다. 대체 경로는 지원되지 않는 환경에서도 같은 학습을 할 수 있는 방법이다. 예를 들어 대화형 계산기가 안 되면 표와 계산 절차로 같은 내용을 학습한다.

## 언제 쓰는가

- 한 주제를 처음부터 끝까지 정리하고 싶을 때
- 다른 사람에게 학습 방법을 공유하고 싶을 때
- 배운 내용을 실제로 쓸 수 있는지 확인하고 싶을 때

## 사전 준비

- 1~7장의 실습 결과물 (비교표, 계산기, 퀴즈, 검증 기록)
- 2장의 가용성 확인 기록
- 메모장

## 단계별 실습

1단계. 세 도구를 정리한다. 4장의 비교표를 개념 비교표로, 각 장의 완료 점검을 실습 체크리스트로, 5장의 계산기를 변수 조절 계산기로 정리한다.

2단계. 사용설명서를 작성한다. 아래 프롬프트 1을 입력해 초안을 받고, 내 환경(2장 기록)에 맞게 고친다.

3단계. 검증 기록을 붙인다. 7장의 검증 기록표 형식을 따라 세 도구의 숫자, 수식, 출처를 확인한 기록을 작성한다.

4단계. 제3자 테스트를 한다. 가족이나 동료에게 패키지를 주고 처음부터 따라 하게 한다. 막히는 지점을 기록한다.

5단계. 대체 경로를 제공한다. 막힌 지점마다 지원되지 않는 환경에서도 학습할 수 있는 대체 방법을 적는다.

## 복사해서 쓰는 프롬프트

프롬프트 1. 사용설명서 통합 요청

```
지금까지 만든 세 도구를 초보자용 사용설명서로 통합해줘. 사용 조건, 입력 예시, 예상 오류, 수동 검증법을 포함해줘.
```

프롬프트 2. 재현 점검 요청

```
위 사용설명서를 처음 보는 사람이 따라 할 때 막힐 만한 지점 3개를 짚어주고, 각 지점의 대체 경로를 제안해줘.
```

## 입력 예시

1~7장의 결과물을 정리한 메모와 함께 프롬프트 1을 입력한다. AI가 세 도구의 사용 조건, 입력 예시, 예상 오류, 수동 검증법을 포함한 설명서를 만들어준다.

## 성공 예시

다른 사람이 설명서만 보고 세 도구를 처음부터 재현한다. 막힌 지점이 나오면 대체 경로로 해결된다. 검증 기록표에 모든 숫자와 수식의 확인 상태가 기록돼 있다.

## 실패 예시

내 화면에서만 동작하는 과정을 그대로 적어, 다른 사람의 환경에서는 재현되지 않는다. 또는 검증 기록 없이 결과물만 공유한다.

## 오류 해결

- 재현이 안 될 때: 막힌 단계를 더 잘게 나누고, 화면 상태를 묻는 확인 질문을 넣는다.
- 환경이 다를 때: 2장의 가용성 기록을 참고해 해당 환경의 대체 경로를 안내한다.
- 검증이 안 된 숫자가 있을 때: 미확인으로 표시하고, 확인 방법을 함께 적는다.

## 완료 점검

- [ ] 개념 비교표, 실습 체크리스트, 변수 조절 계산기를 완성했다
- [ ] 사용 조건, 입력 예시, 예상 오류, 수동 검증법을 포함한 설명서를 썼다
- [ ] 검증 기록표를 작성했다
- [ ] 다른 사람이 처음부터 재현할 수 있는지 확인했다
- [ ] 막히는 지점의 대체 경로를 제공했다

## 확인 문제

1. 사용설명서에 수동 검증법이 들어가야 하는 이유는? 정답: 도구의 결과를 손으로 확인할 수 있어야 AI 오류를 걸러낼 수 있기 때문이다.

2. 제3자 테스트에서 막히는 지점이 나왔을 때 해야 할 일은? 정답: 해당 단계의 설명을 고치거나, 지원되지 않는 환경에서도 학습할 수 있는 대체 경로를 제공한다.
